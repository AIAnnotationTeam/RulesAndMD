
# 【全局】Mac 技术栈约束 (Swift 5.0 / SwiftUI)

本规范定义了 macOS 项目在 Swift 5.0 环境下的开发界限，确保代码的可复用性与稳定性。

## 1. 核心框架
*   **UI 框架**: 必须使用 **SwiftUI**。
*   **版本适配**: 针对 macOS 10.15+。
*   **语言版本**: Swift 5.0。

## 2. 状态管理规则
*   **禁止**: 禁止在 View 内部定义过于复杂的逻辑。
*   **强制**: 所有的业务状态必须放在遵循 `ObservableObject` 的 **ViewModel** 中。
*   **强制**: View 内部仅限使用 `@State` 处理简单的 UI 局部状态（如开关、Hover 状态）。

## 3. 异步与网络 (Swift 5.0 专项)
*   **禁止**: **绝对禁止**使用 `async / await`。
*   **强制**: 异步网络请求（Alamofire）必须使用 **闭包回调**。
*   **结果封装**: 必须使用 `Result<Success, Error>`。
*   **主线程更新**: ViewModel 中的 `@Published` 属性更新必须在 `DispatchQueue.main.async` 中确保线程安全。

## 4. UI 布局与多端适配 (Multi-Platform)
*   **跨平台原生性**: 选择组件时必须优先考虑 **macOS 与 iOS 的通用性**。
*   **适配策略**:
    - **容器选择**: 优先使用 `NavigationStack` 或 `NavigationSplitView`，以便在 iPad/Mac 上展示侧边栏，在 iPhone 上自动折叠。
    - **布局适配**: 利用 `Spacer()`、`GeometryReader` 以及 `.frame(maxWidth: .infinity)` 实现流式布局。
    - **平台差异 (强制)**: **严禁**在 Shared 层使用 `#if os(macOS)` 或 `#if os(iOS)`。必须在 Shared 定义基类/协议，由各平台目录实现对应子类，并由 L0 入口注入。
*   **美学要求**: 
    - 列表项悬停效果必须使用 `.onHover`（Mac 必备）。
    - 必须优先使用 `Image(systemName:)` 调取 SF Symbols。

## 5. 依赖注入 (DI)
*   **强制**: ViewModel 必须通过 `init` 注入所需的 Service 协议。
*   **不可达性**: 严禁在 View 内部直接实例化 Service 对象。

## 6. 数据序列化
*   **强制**: 所有本地化存储（如 UserDefaults 或 JSON 缓存）的数据模型必须遵循 `Codable` 协议。
*   **禁止**: 禁止使用手动字典解析。

## 7. 数据库存储 (SQLite)
*   **选型**: 必须使用 **SQLite** 作为本地持久化方案。
*   **层级归属**: 数据库驱动及原始 SQL 封装归属于 **L3_Infrastructure**，业务 Repository 实现在 **L2_Platform**。
*   **线程安全**: 数据库读写必须在后台线程执行，结果通过 Result 闭包返回主线程。

## 8. 内存管理
*   **强制**: 自定义 ViewModel 中的长周期闭包必须使用 `[weak self]`。
*   **生命周期**: ViewModel 的实例化建议在 L0 的容器或父 View 中通过 `@StateObject`（如果版本支持）或容器注入管理。
## 9. 代码复用性 (Cross-Platform Reuse)
*   **物理隔离与架构对称**: 
    - **Shared 目录**: 必须严格按照 **L1-L3 架构** 组织跨平台逻辑（L1-ViewModel, L2-Service, L3-Model/Util）。
    - **Platform 目录**: Mac 和 iOS 目录各自维护其 **L0_Application** 入口及 **L1_View** 层组件。
*   **原则**: 
  *   **多态抽象模式**: 
    - 对于平台特有能力（如：相册访问、触控反馈、窗口管理），必须在 `Shared/Protocols` 定义抽象接口。
    - 在 `macOS/` 和 `iOS/` 目录下分别继承并实现该接口。
    - **禁止污染**: Shared 目录代码必须保持对具体平台实现的完全无视。

## 10. 依赖管理 (Dependency)
*   **工具**: 统一使用 **CocoaPods** 进行第三方库管理。
*   **Podfile 规范**: 
    - macOS 和 iOS 的 Target 共享同一个 `Podfile`。
    - 共享库放在 `def shared_pods` 中，平台特有库按 Target 分发。
*   **调用规范**: 禁止在 Shared 逻辑中直接调用具体的第三方库 API，必须通过 L3/L2 层的协议进行依赖注入。
