### 2.1 Docker 部署能力与工程约定

**Docker 是本 VPS 唯一的业务部署形式。** 宿主机负责操作系统、Docker Engine / Compose、网络与运维基础设施；业务运行时及依赖写入镜像，生产发布通过容器更新完成。以下是部署要求，尚未核实服务器已具备全部配置。

| 能力 | 提供的功能说明 | 适用业务场景 | 实施边界 |
| --- | --- | --- | --- |
| 镜像构建 | 用 Dockerfile 固化运行时、应用与系统依赖，按需采用多阶段构建 | 可重复交付、减少环境差异 | 在开发或 CI 环境构建；核对服务器 CPU 架构，macOS 构建产物须匹配目标平台；排除真实凭据 |
| 镜像分发与版本 | 从选定镜像仓库拉取产物，发布记录固定标签及 digest | 部署、回滚、环境复现 | 不以浮动 `latest` 作为版本依据；仓库尚未配置确认，拉取权限与网络需验证 |
| Compose 服务声明 | 用 `compose.yaml` 管理单服务和多服务的镜像、网络、卷及启动参数 | 应用、网关及按需辅助组件 | 按项目名隔离部署；配置纳入版本控制，真实密钥除外；属于单机编排 |
| 配置与凭据注入 | 非敏感配置使用运行时变量；凭据按服务授权，支持文件读取的应用使用 Compose secrets | 百炼、存储和支付接入 | 沿用已有平台命名约定；secrets 源文件留在受控主机，不进入镜像与仓库；挂载文件不等于托管加密密钥库 |
| 容器网络与入口 | 服务间通过 Compose 网络通信，仅发布必要入口端口 | 反向代理、API、WebSocket | 数据库和缓存不默认发布公网端口；发布端口同时核对云防火墙和宿主机网络规则 |
| 数据持久化 | 通过命名卷或明确的绑定目录保存数据，分别挂载配置、证书和业务文件 | 数据库、上传文件、证书续期 | 明确目录权限及备份恢复流程；生产应用代码随镜像交付，更新容器不删除数据卷 |
| 资源与日志控制 | 设置并验证服务 CPU / 内存限制、日志轮转和临时文件清理 | 避免单任务耗尽主机 | 所有容器与宿主机共享本机容量；预留系统资源，定期检查磁盘与镜像占用 |
| 健康与退出恢复 | 配置健康检查、常驻服务重启策略和优雅退出 | API、网关、后台执行器 | `unhealthy` 不自动等于重启；重启策略按容器退出行为工作；一次性任务单独设计重试策略 |

部署与配置依据：[Compose 生产部署](https://docs.docker.com/compose/how-tos/production/)、[Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/)、[容器重启策略](https://docs.docker.com/engine/containers/start-containers-automatically/)。

### 2.2 发布、回滚与验收

| 阶段 | 执行要求 |
| --- | --- |
| 首次部署 | 核查 Engine / Compose 版本与功能兼容，验证配置、卷、端口及仓库访问；拉取指定镜像后用 Compose 启动 |
| 更新发布 | 保存当前镜像 digest 与配置版本；需要数据迁移时先备份，更新目标服务后验证健康状态、入口和主流程 |
| 长连接更新 | 为网关设置退出宽限与连接排空策略，客户端支持重连；单机容器替换不承诺无中断 |
| 回滚 | 恢复前一镜像和兼容配置再重建服务；数据库迁移须有独立兼容或恢复方案，镜像回退不会自动回退数据 |
| 上线验收 | 验证重启恢复、持久化数据、日志轮转及业务请求；将实测资源占用作为并发与容量依据 |

## 8. 新项目场景组合与选择边界

以下为基于截图规格的工程建议，未经过本机部署或性能测试。

| 项目需求 | 建议组合 | 是否优先使用当前 VPS |
| --- | --- | --- |
| 轻量后台、内部管理工具 | Docker + 一个应用服务 + 按需持久化 | 适合先评估，验证资源与备份后上线 |
| 需要完整 Node / Python / Java 进程 | VPS 容器 + 已确定运行时 | 适合补足边缘运行时不支持的依赖 |
| 百炼实时语音网关 | VPS 网关容器 + 百炼模型，成品文件按需存 R2 | 先验证杭州到目标服务的链路、首包及连接负载 |
| 离线配音与轻量媒体处理 | 有界任务容器 + 百炼 TTS + 镜像内 FFmpeg | 适合低并发起步；模型生成与本地后处理分开计量 |
| 全球静态分发、对象文件交付 | 优先评估 Cloudflare 对应能力，VPS 承担必要源站服务 | 见 [Cloudflare 能力清单](Cloudflare能力清单.md)，不让小规格主机承担全部文件分发 |
| 大型本地模型或 GPU 推理 | 另选匹配的算力环境 | 截图无 GPU 资源，当前配置不作为该能力依据 |
| 高可用核心服务、重型数据库或高并发转码 | 另行评估扩容、冗余与托管服务 | 当前单实例资源不足以证明可承载，不承诺可用性与吞吐量 |
