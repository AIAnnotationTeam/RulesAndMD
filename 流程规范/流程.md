3.整体技术文档
a.技术栈选型
核心架构：Firebase Hosting + Cloud Run
在这种模式下，Firebase Hosting 不再只托管静态文件，而是作为一个智能网关。
静态资源：由 Hosting 的 CDN 分发（HTML/JS/CSS）。
动态业务/后台：所有的 API 请求（如 POST /api/get-webrtc-token）会被转发到后端容器（Docker）。
并发处理：Cloud Run 支持 1000+ 并发请求/实例，这比 Cloud Functions（1实例1请求）更适合处理频繁的 WebRTC 信令交换。

b.框架选择
全栈框架: Next.js (推荐)
优势: 它们可以将前端 UI 和后端 API (Route Handlers) 写在同一个项目中。部署时，Firebase 会自动将其打包成 Docker 镜像运行在 Cloud Run 上。
