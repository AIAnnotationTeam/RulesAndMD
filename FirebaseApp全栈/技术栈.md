

** Web应用整体基于 Firebase 进行开发 **


# 云后台方案选型
Firebase Hosting + Cloud Run (Docker) 

# 技术栈选型
采用全栈框架: Next.js 
优势: 它们可以将前端 UI 和后端 API (Route Handlers) 写在同一个项目中。部署时，Firebase 会自动将其打包成 Docker 镜像运行在 Cloud Run 上。


# （单仓多包）管理方式
采用的（单仓多包）管理工具为：Turborepo

项目目录结构 (Turbo + Next.js)
repready-web/
├── turbo.json              # Turbo 任务配置文件
├── package.json            # 根目录依赖
├── apps/                   # 应用层
│   ├── admin/              # Next.js - 团队管理管理人员 Web App
│   ├── user/               # Next.js - 销售代表 Web App (含 WebRTC)
│   └── server/             # 服务
├── packages/               # 共享库层
│   ├── ui/                 # 共享 React 组件库 (基于 Figma 设计)
│   ├── firebase/           # 共享的 Firebase Admin/Client 初始化逻辑
│   ├── openai/             # 封装的 WebRTC Session Token 和 RAG 逻辑
│   ├── typescript-config/  # 统一的 tsconfig 配置
│   └── eslint-config/      # 统一的代码规范
└── firebase.json           # Firebase 部署配置
