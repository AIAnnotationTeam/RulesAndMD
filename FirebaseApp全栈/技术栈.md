** Web应用整体基于 Firebase 进行开发 **


# 云后台方案选型
Firebase Hosting + Cloud Run (Docker) 

# 技术栈选型
采用全栈框架: Next.js 
优势: 它们可以将前端 UI 和后端 API (Route Handlers) 写在同一个项目中。部署时，Firebase 会自动将其打包成 Docker 镜像运行在 Cloud Run 上。


# 项目管理方式
采用单一工程结构 (Monolithic Structure)，用户端和管理端通过路由组进行逻辑区分。

项目目录结构
repready-web/
├── app/                       # Next.js App Router (应用逻辑)
│   ├── (user)/                # 【用户端路由组】(URL 不含 /user)
│   │   ├── layout.tsx         # 用户端专属布局
│   │   ├── page.tsx           # 用户端首页 (URL: /)
│   │   └── dashboard/         # 用户个人中心 (URL: /dashboard)
│   ├── (admin)/               # 【管理端路由组】(URL 不含 /admin)
│   │   ├── layout.tsx         # 管理端专属布局
│   │   └── admin-home/        # 管理端首页 (URL: /admin-home)
│   ├── login/                 # 【公共登录模块】
│   │   └── [role]/            # 动态路由 (role 为 'user' 或 'admin')
│   ├── api/                   # 【后端接口】 (Route Handlers)
│   ├── globals.css            # 全局样式
│   └── layout.tsx             # 【根布局】全应用共用
├── components/                # 【可复用组件库】
│   ├── common/                # 通用 UI (Button, Input, Modal)
│   ├── auth/                  # 登录认证相关组件 (如 LoginForm.tsx)
│   └── admin/                 # 仅管理端使用的特有组件
├── lib/                       # 【共享库层 / 工具库】
│   ├── firebase/              # Firebase 初始化逻辑
│   ├── openai/                # OpenAI WebRTC & RAG 逻辑
│   ├── utils.ts               # 工具函数
│   └── db.ts                  # 数据库连接配置
├── middleware.ts              # 【中间件】权限拦截和重定向
├── types/                     # TypeScript 类型定义
├── firebase.json              # Firebase 部署配置
└── next.config.js             # Next.js 配置文件
