# 六大设计原则 (SOLID + LoD)

所有代码都必须遵守以下原则：

1.  **单一职责原则 (SRP):** 一个类只负责一件事。
2.  **开闭原则 (OCP):** 对扩展开放，对修改关闭。优先使用**协议**和**继承+子类重写**。
3.  **接口隔离原则 (ISP):** 使用多个专门的协议来定义不同的功能类型 (如：iOS中 `UITableViewDataSource/Delegate`分别定义了数据源协议和代理协议)，而不是一个协议中包含了多种功能类型。
4.  **依赖倒置原则 (DIP):** 抽象不应依赖具体实现；具体实现应依赖于抽象（协议）。
5.  **里式替换原则 (LSP):** 一个父类对象的方法调用，支持无缝替换为子类对象进行调用，并且调用效果完全一样。
6.  **迪米特法则 (LoD):** 高内聚，低耦合。一个类应尽可能少地了解其他类。

# 业务场景约束

## 页面设计采用：继承 + 组合（目标：功能复用+事件分发）
- 继承的作用：创建一个Base页面类，将公共的功能放到Base页面类中。然后根据不同的业务场景，创建不同的具体页面类，它们都继承自Base页面类，这样所有的业务场景页面都有了Base页面类中的功能了。
- 组合的作用：创建一个BaseHandler类，在里面定义处理业务的基本方法。当有具体的业务类型也处理时，就创建不同的Handler子类，在Handler子类中实现不同的业务处理逻辑。
- 在业务场景页面中，定义不同业务处理类型的Handler子类属性，当业务场景页面中用户点击了对于的按钮，触发业务流程处理时，就根据业务类型，使用不同的Handler子类进行处理。这样可以实现页面中，随着业务代码的增加变得膨胀的问题。
**下面是iOS端的例子，不同的开发框架必须对应到自己的UI组件上**
1.  **继承:** 所有子类页面 `ViewController` **必须**继承自父类页面 `BaseViewController` (父类中包含页面公共功能)。
2.  **组合 (Handler):** 页面 `ViewController` **必须**使用**组合模式**，通过持有子类 `Handler` 属性来处理业务逻辑。


## 流程动态切换采用：桥接模式 -（目标：根据业务类型不同，动态切换到不同的Handler子类）
**下面是iOS端的例子，不同的开发框架必须对应到自己的UI组件上**
**这是 Handler 设计的核心！** 当 `ViewController` 需要动态切换行为时，**必须**使用桥接模式。
1. **步骤 1 (抽象):** `ViewController` 持有一个**抽象的 Handler 基类**（或协议）属性 (例如 `ChatDataFetchHandler`)。
2. **步骤 2 (实现):** 为每种业务场景创建**具体的 Handler 子类** (例如 `NormalChatHandler`, `VIPChatHandler`)。
3. **步骤 3 (连接):** `ViewController` 在运行时，实例化一个**具体的 Handler 子类**并赋值给其 Handler 属性。
