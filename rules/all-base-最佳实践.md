



# 复用原则
1.  **优先复用工程内部组件:** **必须**首先检查工程内的代码，是否已有可复用的组件。
2.  **优先使用第三方库:** 如果 第三方库管理文件(比如：iOS端的Podfile文件，JavaScript项目中的package.json文件等) 中已包含可实现该功能的第三方库，**必须**优先使用。
3.  **主动建议抽象:** 如果新创建的工具在项目中具有通用性，**必须**主动给我提出将其抽象为**公共组件**的建议。

# 视图创建原则
1.  **规则数据列表:** **必须**优先使用 列表组件。
2.  **不规则视图布局:** 使用 容器组件 作为父视图，让里面的内容支持滚动。

# 问题分析和bug修改原则
1.  **分类与泛化:** 首先，对问题进行**分类**，并说明解决这类问题的**最简单、最通用的处理方法**。
2.  **结合项目实际:** 其次，将该方法**应用到当前项目**，结合**整体项目架构**和**设计模式**提供具体解决方案。


# 技术方案选型原则
1. 项目中所有的技术选型和设计 必须是工业级的主流方案，禁止使用临时方案
比如：数据本地存储要使用数据库，禁止使用一个json文件在本地存储。
2. 优先使用系统提供的工具，其次使用已经实第三方库，最后才自己实现     


# 主流程单元测试
在实现了一个功能开发后，必须有主流程单元测试,保证主流程通畅，禁止只写代码而不管代码质量。

# 数据库模型定义原则
1. 如果项目中同时使用到了后台数据库 和 本地数据库时，必须保证两个数据库中同一个表的字段定义完全一样，中间业务代码解析，传递，使用都要完全保持一致。保证从后台数据库来的数据在本地存储，使用，完全是拉通的。


# 生成代码要达到的标准
1. 生成的代码易于阅读（带换行，禁止连续使用简化写法）
2. 生成的代码易于扩展（通过子类，重写父类的方法）
3. 生成的代码必须遵守项目使用的设计模式和项目架构



# 禁止过度设计
1. 设计上要保持实用主义，禁止过度设计，能满足95%的场景就可以了，禁止考虑极端情况。
