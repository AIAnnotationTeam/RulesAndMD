# 四层架构通用规范

## 外部平台能力选型（强制）

外部平台能力遵守 [统一选型规则](平台能力选择原则.md#外部平台能力选型强制)，优先从 [Cloudflare 能力清单](../平台能力/Cloudflare能力清单.md) 和 [百炼平台能力清单](../平台能力/百炼平台能力清单.md) 选择。本文的分层规范约束代码组织，不代表固定绑定云服务商；平台优先级、适用性验证和例外条件统一以该规则为准；用户明确指定、项目约束或清单能力不足等情况，须在方案中记录采用依据。方案须确定实际采用的服务与 SDK，并与对应架构、库清单同步。

| 层级 | 平台能力接入职责 |
| --- | --- |
| L0 Application | 按项目选型装配实现、环境与依赖 |
| L1 Business | 编排业务用例，不直接依赖云服务 SDK |
| L2 Business Architecture | 定义账号、支付、AI 等业务能力契约与复用流程；业务语义适配依赖 L3 |
| L3 Infrastructure | 封装传输、平台 SDK、凭证存储和技术适配；可信服务端承载云端管理与长期密钥 |

平台实现必须遵守现有依赖方向。云数据库、R2、队列和模型等能力在服务端按清单选型，客户端通过业务 API 或受限短期凭证接入；本地数据库、系统推送、原生崩溃监控及商店内购保留各端适配，不机械替换。

# 第三方配置管理（强制）

Node 技术栈本地从 `.env.local` 等环境文件读取标量配置，生产配置与 Secrets 由部署环境注入，禁止将真实配置值写入代码。采用 Workers 的资源绑定从运行时上下文获取，具体遵守 Next 架构规范。其他工程统一在 `Infrastructure/Configuration/AppEnvironment.<平台语言扩展名>` 中定义项目环境配置与第三方常量，其他代码统一引用，禁止分散定义；具体路径以平台架构目录为准。 客户端 AppEnvironment 仅包含可公开配置；Cloudflare 管理令牌、模型长期 API Key、支付私钥和数据库管理凭据只保存在可信服务端。客户端用户会话与短期凭证使用平台安全存储，浏览器公开变量不得包含服务端密钥。

```text
Infrastructure/
└── Configuration/
    └── AppEnvironment.<平台语言扩展名> # 项目环境配置与第三方常量
```

| 层级 | 名称 | 职责 |
|----|----|----|
| L0 | Application | App入口 |
| L1 | Business | 业务模块 |
| L2 | Business Architecture | 业务能力 |
| L3 | Infrastructure | 基础设施 |
 
   
# 分层架构与依赖规则

本 app 采用严格的四层分层结构。在编写任何代码之前，您必须首先确定代码所属的层级。

* **第3层：基础架构层 (Infrastructure)**
    * **职责:** 提供与业务**完全分离**的、通用的、稳定的底层工具 (如: `NetworkManager`, `LogUtil`)。
    * **规则:** L3 **绝对禁止** `import` 或引入 L2, L1, L0。L3 模块间可横向依赖。

* **第2层：业务架构层 (Business Architecture)**
    * **职责:** 提供**业务相关**的、**可复用**的、**标准化**的工具 (如: 标准化 H5 容器, 通用账户 SDK)。
    * **规则:** L2 可依赖 L3。L2 **绝对禁止** `import` 或依赖 L1, L0。L2 模块间**禁止**横向强依赖。

* **第1层：业务层 (Business)**
    * **职责:** 实现具体的业务场景。
    * **规则:** L1 可依赖 L2, L3。L1 **绝对禁止** `import` 或依赖 L0。L1 模块间**禁止**横向强依赖。

* **第0层：应用层 (Application)**
    * **职责:** 作为 APP 壳，通过集成 L1 业务模块，并完成组装和启动。
    * **规则:** L0 可依赖 L1, L2, L3。L0 不应包含业务逻辑。
